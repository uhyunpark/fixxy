# Static spectral FIR primitive port

Date: 2026-09-11. Scope: Stage 3 of `.agents/skills/dsp-pipeline/SKILL.md`,
limited to the independently passed static synthesis/renderer gates. These are
our DSP approximation; no soothe sonic-equivalence claim is made.

## Implementation and ownership

`src/dsp/SpectralFir.h` adds three JUCE-free, header-only double-precision units:

- `SpectralFirSynthesis`: preallocated real-cepstral minimum-phase synthesis,
  default design grid M=16384 and L=4096 taps. Input is already on the exact
  M/2+1 positive-frequency grid. Reduction clamps to [0,40] dB; unity is exactly
  `[1,0,...]`. It ports the verified natural-log/lifter/exponential/truncation
  recipe without a window, DC normalization, or an interpolation layer.
- `SpectralFirKernel`: immutable prepared coefficients, a 64-sample direct
  head, and J ordinary zero-padded 128-point real-FFT partition spectra.
  Nonmultiple lengths pad the final partition; tested lengths include 1, 17,
  65, 256, 4096, and 4097. This is not a linear-phase synthesis implementation.
- `SpectralFirConvolver`: one channel of causal rendering. It owns a P=64
  direct-history ring and J+1 retained input spectra. Kernels must outlive every
  referencing renderer and remain unchanged while rendering. Preparation,
  replacement, and destruction belong off-thread.

The renderer ports `Z_b=sum(F_j*X_(b-j), j=1..J-1)`. With static coefficients it
retains the preceding inverse transform's second half as overlap, instead of
recomputing that same preceding transform each block as the Python oracle does.
The direct head uses the current input sample. Internal P boundaries persist
across arbitrary host callbacks; no output FIFO or algorithmic buffer delay is
introduced. No windows or STFT/COLA normalization occur in this path.

The only other edits for this port are `test/spectral_fir_test.cpp`, additive
`SpectralFirTest`/`SpectralFirScalarTest` CMake targets, and their pre-commit hook
registrations. The fixtures remain generated by the Stage 2 agent's
`proto/dump_spectral_fir_fixtures.py`. No plugin, public mode, schema, processor,
UI, `SpectralNode`, or rejected transition path is integrated.

## Audio-thread audit

There is no `processBlock()` integration in this patch. The prospective audio
entrypoint is `SpectralFirConvolver::process()`:

- Allocation/deletion: none in rendering/reset; storage is fixed by `prepare()`.
  Runtime interception of ordinary C++ `new`/`new[]` and sized/unsized
  `delete`/`delete[]` reports **0 allocations / 0 deallocations** across long
  rendering, ring wrap, reset, and short/nonmultiple-length paths. This is not
  an interception of C `malloc`/`free` inside Apple's FFT implementation.
  `SpectralFft` source audit confirms vDSP setup construction/destruction only
  in prepare/destruction and preallocated split buffers during transforms.
- Locks, I/O, logging: none. No mutexes or atomics are introduced in the DSP
  primitives. Test output and timing calls occur only outside rendering.
- Bounded work: exactly 64 direct multiply-accumulates per sample. Each internal
  P boundary executes one forward and one inverse 128-point FFT, and
  `(J-1)*(P+1)=4095` complex products/accumulations at L=4096. A callback of N
  samples crosses at most `ceil(N/P)` boundaries. The spectrum slot wraps within
  J+1; there is no growing absolute sample/block counter or unbounded queue.
- Parameters: kernels are static. There are no unsmoothed runtime setters or
  implied crossfade behavior. Dynamic target smoothing/admission is unported.
- Synthesis: allocation-free after prepare but explicitly designated off-thread
  because its three M-point FFTs and binwise transcendental work are substantial.
  Kernel spectrum preparation allocates and must remain off-thread.

Default explicit numeric storage (excluding object/vector bookkeeping and the
opaque vDSP setup) is 67,072 bytes per kernel, 73,248 bytes per renderer, and
393,232 bytes per M16384 synthesis workspace on vDSP. Four distinct kernels
(two banks x stereo), four renderers, and two synthesis workspaces require
1,347,744 bytes (about 1.29 MiB), before output tap buffers or future detector/history
sharing. The scalar FFT has additional fixed precomputed twiddle/bit-reversal
storage. No capacity grows while rendering.

These are observed finite-run wall-clock maxima, not a worst-case real-time

749 to 613 us on vDSP after the arithmetic optimization (about 18 percent).

Static rendering is inexpensive, but these partial-path measurements cannot
authorize synchronous synthesis in `processBlock()`: detector work, kernel
partition construction, new-bank history initialization, and the unresolved
transition admission policy are excluded. A worker does not solve unsustainable
average target-generation throughput. Full-path sample-rate-specific C++
timings remain required before engine integration.

## Remaining integration gates

This completes the static primitive scope only. A cap-safe dynamic transition,
full-history warm-start policy, background synthesis cadence/admission,
control/detector port, latency/mode alignment, plugin integration, and visual
signal checks remain outside this patch. Endpoint-only fades are deliberately
absent because the Stage 2 cap counterexample rejected them. No linear-phase
synthesis has been ported without its own generated fixtures.

Pluginval strictness 5 is a product gate, not evidence for these currently
unintegrated classes. This primitive agent has not rerun pluginval; the lead
agent owns the fresh whole-plugin validation and records it separately. No
commit is created, and primitive success does not mark product parity complete.
